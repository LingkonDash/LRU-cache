# LRU Cache Implementation in JavaScript

An efficient **Least Recently Used (LRU) Cache** implementation in JavaScript, supporting **$O(1)$ average time complexity** for both `get` and `put` operations, with optional **TTL (Time-To-Live / Expiration)** support.

---

## 📌 Data Structures Used & Rationale

1. **Hash Map (`Map`)**:
   - Maps each key directly to its node in the Doubly Linked List.
   - Enables **$O(1)$ lookup time** for `get(key)` and checking key existence in `put(key, value)`.

2. **Doubly Linked List (`Node` with `prev` & `next` pointers)**:
   - Stores key-value entries sequentially in order of recency.
   - Allows **$O(1)$ insertion** at the head (Most Recently Used / MRU).
   - Allows **$O(1)$ removal** from anywhere in the list when given a node reference.
   - Uses **Dummy Head & Dummy Tail** nodes to eliminate null checks during additions/deletions.

---

## 🔄 How LRU Ordering is Maintained

- **MRU (Most Recently Used)** items stay right after the **Dummy Head**.
- **LRU (Least Recently Used)** items sit right before the **Dummy Tail**.
- **`get(key)`**: If the key exists, its node is detached from its current position and inserted right after the `head`.
- **`put(key, value)`**:
  - If the key exists, update its value and move its node to the `head`.
  - If the key is new, add a node after `head`.
  - If the capacity is exceeded, remove the node before `tail` (LRU) and delete its entry from the Map.

---

## ⏰ Time & Space Complexity

| Operation | Time Complexity | Description |
|---|---|---|
| `get(key)` | **$O(1)$** | Map lookup + Doubly Linked List node re-linking. |
| `put(key, value)` | **$O(1)$** | Map lookup/insertion + Doubly Linked List node insertion/eviction. |
| Space Complexity | **$O(N)$** | Where $N$ is the specified maximum capacity of the cache. |

---

## ⏱️ Bonus Feature: TTL / Expiration Support

- **Approach**: An optional `ttlMs` parameter can be passed to `put(key, value, ttlMs)`. The node records `expiresAt = Date.now() + ttlMs`.
- **Behavior**: On `get(key)`, if `Date.now() > node.expiresAt`, the key is lazily evicted from both the list and the map, returning `-1`.
- **Trade-offs**: Lazy eviction consumes $O(1)$ overhead on access without needing background cleanup timers. Active background timers would consume extra CPU/memory resources.
